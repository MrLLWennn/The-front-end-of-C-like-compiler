# 构建预设与重复验证

将配置、构建和测试绑定到相同设置，减少手写目录或开关不一致造成的误用。CMakeLists仍负责组织目标与测试；预设只保存调用约定，不实现编译器功能。

## 配置继承

隐藏的base设置Unix Makefiles、Debug、BUILD_TESTING=ON和CMAKE_EXPORT_COMPILE_COMMANDS=ON。frontend-debug与llvm-debug继承这些设置，分别关闭和启用MY_COMPILER_ENABLE_LLVM，并各自使用build-presets下的独立目录。

configurePresets的cacheVariables与显式-D选项作用对应；binaryDir指定生成缓存和构建规则的位置。buildPresets通过configurePreset使用同一目录，jobs=2限制并行构建数量。testPresets也引用该配置，outputOnFailure打印失败细节，noTestsAction=error拒绝零测试成功。

## 两条工作流

```bash
cmake --workflow --preset frontend-check
cmake --workflow --preset llvm-check
```

workflow依次执行configure、build、test；所有步骤都引用同一套配置。前端工作流预期8项，LLVM工作流预期11项，原有测试不增不减。列出预设可用cmake --list-presets=all，单阶段可用cmake --preset frontend-debug、cmake --build --preset frontend-debug和ctest --preset frontend-debug。

原项目显式配置方式最低CMake3.22；本文件版本6和workflow需要3.25以上。CMake不会自动安装Python、Graphviz或LLVM，缺依赖时应按配置错误定位，不通过忽略测试或改断言来获得成功。

## 怎样核对新入口

分别运行两条工作流，检查binaryDir、LLVM开关、构建目标和最终测试总数。前端测试应使用build-presets/frontend-debug中的程序；LLVM测试使用build-presets/llvm-debug，并包含原生链接运行检查。不要拿原build-llvm的通过记录替代新目录的实际运行。

本次只改变配置入口和文档，不改变语言语义或后端算法。2026-10-24使用者已运行两套新入口，前端8/8与LLVM18.1.3配置11/11通过；配置目录和测试日志均已核对。JSON静态校验与实际运行验证分别记录。

## 个人配置与编辑器

CMakeUserPresets.json用于本机路径和选项，已列入.gitignore；共享CMakePresets.json可以随项目提交。compile_commands.json供支持该格式的编辑器工具读取，生成文件不等于已配置完成全部IDE功能。已有build和build-llvm缓存不删除、不覆盖。
