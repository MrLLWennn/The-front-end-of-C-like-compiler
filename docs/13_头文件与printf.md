## 实际支持边界

| 项目 | 本轮实现 |
|---|---|
| 本地头文件 | #include "file.h"，相对包含者目录查找，递归展开 |
| 包含保护 | 常见#ifndef/#define/#endif、#ifdef/#else、#pragma once；无保护递归报错 |
| 宏 | 空宏及无参数的非负十进制整数常量宏，不在字符串内替换 |
| 函数声明 | int函数，参数需要int及名字，声明/定义检查参数数量相容性；重复相容声明允许 |
| stdio.h | 为本翻译单元导入手写的受限printf契约；不展开glibc平台头文件 |
| printf | 真实系统C库调用；格式串必须为字面量，%d/%i/%c/%s/%%，限定标志及固定宽度 |
| 字符串 | UTF-8字节、保留空白及注释标记；支持\n、\t、\r、\\和\"转义 |
| 类型 | 普通变量、参数与返回值仍为i32；字符串只用于printf的格式及%s实参 |

仍不支持其他系统头文件、函数宏、宏表达式、#if算术条件、宏生成的include、行拼接、动态格式串、浮点格式、%n、任意指针/字符数组、标准库其余函数或多个源文件分别编译。%s仅接受字符串字面量，%c使用int字符码。整数宽度最大1024；不支持动态宽度和精度。

这里的stdio.h是显式的库接口适配层：它向本翻译单元声明printf能力，不是在自己的Parser里处理完整系统头文件。它也不提供完整C的块级头文件声明可见性或所有预处理规则。不能在简历中缩写成“兼容任意C头文件”或“实现完整C预处理器”。

## 为什么不直接把stdio.h原文塞给旧Parser

真实系统头文件还包含大量类型定义、属性、平台宏和嵌套声明。把它交给目前只有int子集的Parser，不能只加一条printf产生式就完成兼容。

本轮分开处理两种需求：自己的.h真实展开并进入原Lexer和Parser；stdio.h只导入已明确实现的printf接口。这样可以诚实地完成“包含本地声明、计算并打印结果”的程序，不把接入一项库调用说成完整C兼容。Clang对照程序则由Clang自己处理真实系统头文件。

## 每层的前后变化

### 1. 预处理：从单个源文件变为源文件及其依赖

新增front_end/preprocessor.cpp及preprocessor.hpp。Processor::expand读取源码，先用状态机去注释，再识别预处理指令、处理包含保护和递归展开本地头文件。普通行中的整数常量宏只在完整词素边界替换，字符串和字符引号内保持原字节。

注释状态机以前只区分普通代码与注释，现在还区分引号内文本及反斜杠转义。`printf("http://demo/*keep*/  x\n")`中的//、/*、双空格都必须留下；`int/**/value`则需要在去注释后留下分隔空格，不能拼成intvalue。

包含栈检查无保护循环，#pragma once及完整文件的包含保护用于去重。限制嵌套32层、单文件1MiB、累计读取8MiB，避免错误包含无限展开。这是有边界的预处理实现，没有承诺完整C预处理语义。

全部依赖先读入，再把它们与17个生成文件逐一检查路径及文件实体是否重合，确认后才写01-uncomment.txt。因此即使头文件恰好叫15-ast.txt，或通过硬链接与某个输出重合，也不会先截断输入。

### 2. Lexer：保留整个字符串Token

新增TokenType::STRING及is_string。字符串Token保存包含引号和转义的原始字面量，AST Builder随后解码为实际字节。换行、NUL、未闭合字符串和未支持的转义明确报E_LEX_STRING，不继续交给Parser。

去空白步骤只压缩引号外的空白，引号内逐字复制。运算符扫描也改为peek确认：只有确认是==、<=、+=等复合Token时才消费第二个字符，其他字符留给下一轮。这样`value=(2+3)*4`中的左括号不会被等号扫描误吞，也不会为了判断运算符而重复累计空白行列。

### 3. 原Parser和AST Builder各做自己的事

原文法的factor增加string-literal，Parser把String Token映射到该终结符。原表驱动语法检查没有被绕过，新测试仍要求留下“预测分析结束”。

AST新增String和调用语句；在函数参数列表后遇到分号，记录declaration_only原型。原型没有函数体和return，后端不能为它再生成一份定义。函数声明与定义可以有不同参数名字，但本子集中参数数目和int类型必须相容。

### 4. 语义：在生成不匹配的可变参数调用之前拒绝

FunctionSignature同时记录参数数量、是否已有定义及是否printf契约。调用仍要求有可见的声明或定义；同名重复定义及不相容声明失败。

printf具有专门的格式检查：先要求字面量格式串，解析转换项，再对照实参数量及每一项的类型。%d/%i/%c要求int，%s要求字符串字面量；普通int表达式中出现字符串则报E_SEMA_TYPE。普通表达式、作用域和未初始化检查继续生效。

这不是可有可无的显示检查。可变参数调用没有普通固定参数那样完整的运行时类型信息，若格式把一个整数当指针使用，可能造成错误访问。因此本子集不支持的格式必须先拒绝，而不是生成一个LLVM结构合法、运行时却不匹配的调用。

### 5. LLVM与链接：声明接口，调用系统实现

String节点使用CreateGlobalStringPtr生成带结尾NUL的全局常量。stdio契约在Module中建立`i32 (ptr, ...)`函数类型：固定首参数为格式串指针，后面是可变参数。int值已经是i32，字符串值为ptr；CreateCall生成调用。

后端先合并函数签名，再只为真正的定义生成函数体，避免头文件原型和后续定义变成两个同名LLVM函数。printf没有本项目提供的函数体；目标文件里可以保留未解析的外部符号，Clang驱动链接时由系统C库提供实现。

LLVM官方[函数类型说明](https://llvm.org/docs/LangRef.html#function-type)也用printf展示可变参数接口；[Clang命令说明](https://clang.llvm.org/docs/CommandGuide/clang.html)区分预处理、编译及链接阶段。本轮借鉴这些接口和职责划分，不声称重写了Clang或libc。
