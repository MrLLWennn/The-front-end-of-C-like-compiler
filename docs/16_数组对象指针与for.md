# 数组 对象指针与for

## 关键函数怎样工作

`Type::pointer/array/decayed`保留类型结构。例如int a[2][3]是2个“含3个int的数组”；作为参数时只退化最外层，因此每次行偏移仍跨越3个int。LLVM虽然使用opaque ptr，前端仍必须保存所指类型，否则无法决定GEP的步长。

`Builder::type/dimensions/initializer`分开读取基础类型、星号、声明名后的数组维度和初始化。外层数组可以从列表或char字符串推断长度，内层必须明确。多维初始化当前要求逐层花括号，不实现全部C括号省略规则。原表驱动Parser仍先检查文法；新文法将声明、后缀和赋值拆开，不再把赋值左侧变量临时改名成identifier1。struct定义/普通声明、void参数及强制转换保留明确的前瞻分派，不宣称整个C文法都是LL(1)。

`Checker::place`负责“这个表达式指的是哪个可写对象”；`expression`负责“读取它会得到什么类型”。&只取得地址，*与[]先检查指针/下标类型，再构成左值；->按解引用后取成员处理。数组整体不是可赋值左值。指针相加、void*偏移、浮点下标、未初始化的指针变量等有独立拒绝用例。

`Lowering::address`统一生成变量、成员、数组元素和解引用的地址。数组作为表达式时生成0,0 GEP取得首元素地址；pointer+n用所指类型作为GEP元素类型，不是直接加n字节。指针差使用元素大小换算，本子集把可表示的差值返回i32。C中的越界、跨对象相减或悬空指针仍是调用方必须避免的无定义行为。

`Lowering::initialize`对有初始化列表的数组先补零，再覆盖明确给出的元素。普通无初始化数组不会被默认清零。`Update`和复合赋值先求一次目标地址，再读取旧值、计算并写回；后缀返回旧值，前缀返回新值，避免把a[i++]中的i重复增加。

`For`先建立循环作用域并执行初始化，再生成condition/body/step/end四个块。循环体结束跳到step，step再回condition；空条件按true处理。零次执行时仍完成初始化，循环后的名字表移除循环变量；alloca仍统一放函数入口，撤去名字不等于主动释放栈槽。

## 初始化与内存安全的边界

未取地址的直接标量和结构体叶成员仍做确定初始化检查，if合流取交集，循环体赋值不冒充必然执行。对象取地址后标记escaped，后续不再把直接初始化集合当成完整别名证明；数组内容与间接写入也没有完整的数据流分析。这是明确的保守能力边界，不是通过地址传递就证明值已初始化。源码通过编译仍可能包含越界、未初始化内容、空/悬空指针、字符串常量写入等错误，不能把测试通过说成内存安全认证。

支持普通对象指针及多级指针、结构体自引用指针、void*与对象指针的转换、字面量0空指针；不支持函数指针、括号声明器、VLA、const/volatile、sizeof、malloc/free头文件契约和完整标准库。外部结构体按值ABI仍受原限制；对象指针接口新增与Clang双向互调验证。

## 验证方法

1. 前端预设运行全部注册回归；LLVM预设额外运行原生代码对照。
2. 正例保留源码哈希；本编译器分别生成O0/O2目标文件，再由Clang驱动链接。独立另一条路径让Clang直接编译相同C源码。
3. 比较两路标准输出、标准错误、退出码，并和手算或宿主Python计算的预期核对。专门包含返回5的程序，避免把“只能返回0”误当正确。
4. 固定随机种子生成小规模数组求和例子；双向ABI夹具让Clang调用本编译器生成的指针函数，也反向调用Clang函数修改数据。
5. 反例核对诊断编号、原Parser完成、输入字节未改变，以及失败时没有发布新的AST/IR/目标文件。故意无限for仅检查构建，不运行或算入运行次数。

测试只证明已覆盖的行为；没有测量编译性能或生成程序提速，也没有证明全部合法C程序正确。O0表示不运行中端优化管线，O2复用LLVM标准管线，不是自研两个优化器。
