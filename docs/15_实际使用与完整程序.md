# 实际使用受限C编译器

2026-10-26。CP05当前前端12/12、LLVM18.1.3配置19/19全量回归通过；typed样例O0/O2均退出0，标准输出与Clang及预期一致。本文说明怎样从C源码得到并运行本编译器生成的程序。本轮按用户授权直接完成构建、测试与Git发布；命令仍保留供复现。

## 目前能完成什么

现在已经可以处理一份简易但完整的受限C程序：源码中有main入口，能够使用多个函数、本地头文件、局部变量、分支、while循环、数值转换、结构体及受限printf；本编译器完成前端检查、LLVM IR构造、优化和目标文件生成，再由Clang驱动链接为本机可执行文件。

“完整程序”说的是从源码到实际执行的链路已经走通。语言范围仍有限：不是任意标准C源文件、任意头文件或库都能直接编译。详细支持清单见[多类型与结构体说明](14_多类型函数与结构体.md)。

## 方式一 运行已经通过的展示程序

在仓库根目录执行：

```bash
cd /home/fridayyy/files/prepare/projects/compiler
python3 examples/run_mini_c.py \
  build-presets/llvm-debug/my_compiler --example typed --opt-level 2
```

输入是examples/typed_structs.c及typed_structs.h。main取得结构体结果，调用float/double计算函数和void输出函数，生成程序打印：

```text
value=3.00 grade=A accepted=1
score=3.50
```

脚本负责把编译、链接、执行和Clang独立对照连起来，并创建新的输出目录、保留日志和result.json。它不会替你构建编译器，也不执行Git。--opt-level 0可查看未运行标准优化管线的IR；--example stdio/basic可运行之前的整数程序。

## 方式二 亲自分三步完成

下面仍使用已验证的typed样例，但直接调用编译器，便于看清每个工具做什么：

```bash
cd /home/fridayyy/files/prepare/projects/compiler
mkdir -p "$PWD/build-mini-c-runs" &&
manual_run=$(mktemp -d "$PWD/build-mini-c-runs/manual.XXXXXX") &&
"$PWD/build-presets/llvm-debug/my_compiler" \
  --input "$PWD/examples/typed_structs.c" \
  --grammar "$PWD/files/04-grammar.txt" \
  --output-dir "$manual_run/output" \
  --emit llvm \
  --opt-level 2 &&
clang-18 "$manual_run/output/18-program.o" -o "$manual_run/program" &&
"$manual_run/program"
```

- 第一步：my_compiler读取源码及文法，展开本地头文件，完成词法、语法、语义及LLVM生成；成功后output目录中有18-program.o。
- 第二步：clang-18读取这个目标文件，组织启动代码和系统C库等链接依赖，输出program。这里传给Clang的是.o，源码由my_compiler处理。
- 第三步：执行program，运行输入C程序中的main。printf内容来自生成的程序，阶段说明来自编译器或演示脚本。

manual_run使用新目录，避免把本次与旧产物混淆。单独运行最后一条命令后，紧接着使用printf 'program_exit=%s\n' "$?"可以查看被运行程序的退出码；不要在中间插入其他命令再读$?。

## 换成自己写的C文件

把上面--input后的路径替换为自己的.c文件，仍保留仓库提供的04-grammar.txt。无需为了每份源码重建编译器，也不要把C源文件传给CMake当成本编译器项目源码。

例如可用nvim新建examples/my_program.c，并按已经支持的语法编写：

```c
#include <stdio.h>

double square(double value)
{
    return value * value;
}

int main(void)
{
    double answer = square(2.5);
    printf("answer=%.2f\n", answer);
    return 0;
}
```

它展示的是现有受限语法的写法；具体输入仍应实际编译运行验证。给函数使用命名参数；在调用前给出声明或定义，自己调用自己允许。源文件中的#include "api.h"相对包含者所在目录查找，自己的头文件也必须只使用当前支持的语法。

如果只想看AST，把--emit llvm改为--emit ast并去掉--opt-level；这种模式不会生成.o，也不能随后拿它链接。对原有语法样例，若想查看旧符号表和DOT语法树展示路径，使用--emit legacy；新类型的完整语义/生成能力按ast/llvm路径验收。不同模式的产物不同，不能仅凭某个旧文件存在就判断本次成功。

## 参数和产物

| 参数 | 用途 |
|---|---|
| --input | 输入C源文件 |
| --grammar | 当前表驱动Parser使用的文法文件 |
| --output-dir | 本次中间文件和最终目标文件目录 |
| --emit llvm | 运行AST/语义检查及LLVM后端 |
| --emit ast | 只到受限AST与语义检查 |
| --emit legacy | 旧前端分析及语法树路径 |
| --opt-level 0或2 | LLVM模式的优化级别 |

| 产物 | 用来检查什么 |
|---|---|
| 03-lexer.txt | 实际词法单元 |
| 10-stack_file.txt | 原表驱动Parser的推导过程 |
| 15-ast.txt | AST、类型和程序结构 |
| 16-before.ll | 优化前LLVM IR |
| 17-after.ll | O0保留或O2优化后的IR |
| 18-program.o | 本编译器生成的原生目标文件 |
| program | 手工链接命令生成的可执行文件；演示脚本中名为mini_c |

编译器退出0表示本次编译完成；1表示编译或文件等执行失败；2表示参数/配置用法错误。这与生成程序自身的main返回值不同。仅有.o不代表链接和运行已经成功。建议使用&&连接各步：前一步失败就停止，避免拿旧产物继续运行。

## 写程序时的当前限制

- 使用int、float、double、char、bool；void用于函数返回或无参数列表，不能声明void变量。bool可配合受限stdbool.h契约使用。
- 只支持加、减、乘及六种比较；支持前后缀++/--、for及+=/-=/*=；暂不支持除法、取余、逻辑短路或break/continue。
- if/else和while使用花括号；非void函数必须在顶层末尾return一个值，暂不支持分支内提前return。void函数允许return;或直接结束。
- 结构体先在顶层完整定义，再声明对象或函数签名。成员逐个赋值，或者从同类型的完整对象复制；结构体花括号初始化仍未实现；固定数组及对象指针见docs/16_数组对象指针与for.md。
- 结构体按值函数只在同一翻译单元互调，没有实现跨外部C库的通用聚合ABI。
- printf格式串必须为字面量；%s接受字符串字面量或char指针，浮点使用%f/%e/%g等受支持格式，不支持动态格式和完整标准库。
- int固定i32回绕加减乘，char为有符号8位。浮点转整数等窄化转换应使用有限且结果可表示的输入。源位置主要对应预处理文件，尚未完整映射回原文件。

当前12/19项测试及CP04的71/103项类型用例只证明已覆盖的行为；没有测量编译器或生成程序的性能。本轮可以阶段收束为可演示工程，面试材料不写成完整C兼容或自研LLVM优化算法。


## 数组与指针综合演示

在仓库根目录执行：

```bash
python3 examples/run_mini_c.py build-presets/llvm-debug/my_compiler --example memory --opt-level 0 --output-root build-memory-demo
python3 examples/run_mini_c.py build-presets/llvm-debug/my_compiler --example memory --opt-level 2 --output-root build-memory-demo
```

样例用数组保存double数据，指针参数原地缩放，for和指针遍历求和，再通过结构体指针读取结果，输出`count=4 total=15.0 label=verified`。运行器保留AST、IR、目标文件、两路可执行文件和JSON。它不自动构建编译器。
