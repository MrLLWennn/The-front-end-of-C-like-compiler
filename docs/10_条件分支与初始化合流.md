## 语义边界

- 条件使用已有int表达式，零为假、非零为真；可以是参数、已初始化局部变量或加减乘表达式。
- if与可选else的主体都必须使用花括号；支持块内嵌套if。不带else时，假路径直接进入汇合点。
- 继续要求函数最外层以唯一一条return结束。不支持分支内return、循环、break/continue、函数调用、数组后端或完整C。
- 直接else if未纳入子集，写成else块内嵌套if。关系/逻辑运算及bool/浮点条件尚未加入受限AST，原Parser语法通过不代表新后端支持。
- 原文法仍要求每个块的声明位于语句之前。初始化检查保守分析两条路径，不做常量条件/路径相关性证明；分支结束后再赋值仍允许通过。

前端分析条件表达式与可见性，不为任意运行时参数提前选路；生成程序运行时执行条件比较和跳转。词法块决定名字可见性，基本块决定执行路径。

## AST与所有权的前后变化

include/my_compiler/ast.hpp新增StatementKind::Conditional。原Declaration/Assignment/Block成员保留；新增condition、then_branch、else_branch三个unique_ptr，分别拥有条件表达式和两个块，else_branch可为空。没有复制AST子树。

这是沿用统一Statement结构的最小增量，各种语句都携带新增指针字段，有额外空间成本。当前尚未测量AST内存和编译耗时；后续节点种类/规模扩大时再评估variant或分层节点，不把本次新增功能称为AST内存优化。

## 初始化合流：先分开分析，再求交

check_statement遇到Conditional：先检查条件表达式可读，再分别复制进入时的Scopes，检查两个分支。缺少else时，else_scopes保持进入状态。

```cpp
auto then_scopes = scopes;
auto else_scopes = scopes;
check_statement(*statement.then_branch, then_scopes, file);
if(statement.else_branch)
    check_statement(*statement.else_branch, else_scopes, file);
```

两个花括号主体分别压表/弹表，分支内新声明不会泄漏。合流只处理进入时已有的“同一作用域层＋同一名字”，不能把内层同名声明当成外层变量的初始化。

```cpp
entry.second.initialized = then_scopes[i].at(entry.first).initialized &&
                           else_scopes[i].at(entry.first).initialized;
```

两支正常到达时，只有两边均确定初始化，合流后才确定可读。int y; if(flag){y=1;} return y拒绝；两边都赋值则可通过。若先用共享状态分析then再分析else，then的赋值会错误地掩盖else里y=y+1的未初始化读取，因此专门设置cross_path_read负例。

这是一种结构化、保守的确定初始化分析。当前无分支return，所有分支都可正常到达；以后支持提前返回时，应仅合并可达的正常后继。循环还需要另一套迭代/不动点处理，当前没有实现。

实现成本是每个if复制两份可见绑定，时间和临时空间随可见名字数量增长。先以清楚可测的实现建立正确性，未测编译耗时，也没有加入增量状态/持久化表等优化。

## LLVM生成与嵌套插入点

后端沿用参数/局部变量到AllocaInst*的映射；条件表达式求值后CreateICmpNE与i32零比较得到i1。创建if.then、可选if.else和if.end，CreateCondBr连接两支，分别SetInsertPoint生成语句，最后CreateBr进入汇合点。后续源码语句从if.end继续生成。

进入内层if会改变Builder插入点，因此外层分支结束时直接从Builder当前块CreateBr，不能回到最初then块再追加终结指令。本阶段禁止分支return，故每个分支递归生成完成后都有一个尚待连接的正常出口。

原始IR通过同一槽位承接不同路径的store，汇合点load。前端不手写phi；LLVM标准O2可做适用的提升与简化，可能得到phi、select或其他等价形式。测试允许这些不同结果，不把“没看到phi”直接判为错误。没有新自研Pass或速度主张。

## 导师与HR视角的预测追问

**条件在哪里判定？** 前端检查表达式及名字是否合法，后端生成比较和跳转，依赖输入的真实选路发生在运行时；优化器可对已知常量做简化，但不是前端替任意输入执行程序。

**为什么给两支复制状态？** 两条路径从同一前置事实出发，不能互相借用初始化结果；合流后取两支共同确定的事实。内层遮蔽的变量按层和名字区分。

**为什么不直接写phi？** 当前统一使用槽位表示可变变量，可先生成清晰的控制流和读写，由成熟LLVM管线处理适用提升。代价是O0多读写，收益是前端不承担通用SSA构造。

**增加if是否只修改后端？** AST表达条件与分支，语义检查处理路径事实，后端建立CFG，回归验证正反例和结果，缺一层都可能产生错误。

**怎样证明工作有效？** 以实际构建/诊断/O0与O2原生结果为依据；本轮尚待执行，简历不提前加入新完成项。用cross_path_read及nested_else说明如何让测试命中路径污染和嵌套插入点错误。
