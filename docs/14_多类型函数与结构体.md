# CP04：多类型函数与结构体

2026-10-26。按使用者新增要求扩展；源码、样例和回归用例已准备，本轮C++构建、测试和运行尚未由使用者执行。前一版CP03的10/10、15/15及演示记录只证明前一版，不算本轮通过。

## 1. 本轮支持的内容

| 对象 | 本轮实现范围 |
|---|---|
| 基础类型 | int、float、double、char、bool；void用于函数返回及无参数列表 |
| 函数 | 相应类型的参数、返回值、原型、定义、嵌套调用；检查完整签名相容性 |
| void | 顶层末尾return;或直接到函数结尾；禁止把void调用当作数值 |
| 数字 | 十进制整数；小数及科学记数法；浮点f/F后缀；正负号 |
| 字符 | ASCII字符字面量及\n、\t、\r、\0、\\、\'、\"；字符常量类型为int |
| 数值运算 | +、-、*与六种比较，进行整数提升及公共数值类型转换 |
| 数值转换 | 初始化、赋值、实参、返回处隐式转换；也可写(double)x等数值强制转换 |
| 结构体 | 顶层具名定义；基础类型及先定义结构体成员；局部对象、嵌套成员读写、整值复制 |
| 结构体函数 | 同一翻译单元内按值传参及返回；含结构体签名的LLVM函数设为internal |
| 初始化检查 | 按叶成员路径跟踪；分支对每个成员求交，while保守保持入口状态 |
| printf | 旧格式保留，新增%f/%F/%e/%E/%g/%G及固定精度；float提升为double，char/bool提升为int |
| 头文件 | 原有本地包含与stdio契约保留；新增stdbool.h的有限契约，bool/true/false仍是本语言直接识别的词素 |

int固定为有符号32位，char固定为有符号8位，bool表示真/假；float和double分别映射LLVM float/double。当前标量ABI对接面向本机x86_64 Linux的clang-18。整数加减乘仍采用原来的32位回绕规则，不等同标准C对有符号溢出的规定。浮点没有添加fast-math；涉及浮点转整数的输入应有限且结果可表示，不承诺越界转换结果。

本轮没有扩展long/short/unsigned等尚未登记的类型，也未实现typedef、const/volatile类型限定语义、指针/地址运算、数组、匿名/局部结构体定义、结构体花括号初始化、联合体、位域、sizeof、完整系统头文件或通用C ABI的聚合参数分类。仍不支持除法/取余、逻辑短路、for、break/continue和分支内提前return。非void函数仍要求唯一的顶层末尾return。main限定为int main(void)或int main()。

## 2. 为什么不能只替换函数开头的int

旧实现有四处相互依赖的默认假设：AST没有记录类型；名字绑定只记是否初始化；LLVM函数签名及槽位统一i32；运算与printf参数直接用i32。只让Builder接受double关键字，会出现“源码说double、IR实际仍是i32”的错误。

新链路把类型带到底：

```text
Type/结构体成员声明
    -> AST Builder记录声明和字面量类型
    -> Checker核对名字、成员、初始化、签名和转换
    -> 表达式写回结果类型、公共运算类型和成员索引
    -> Lowering按类型创建签名、存储、转换和运算
    -> LLVM校验 -> O0/O2 -> .o -> Clang链接 -> 运行对照
```

原Lexer与表驱动Parser仍先执行。文法新增char、结构体类型、成员链、字符字面量和数值强制转换；布尔值通过factor进入完整表达式，不再用旧快捷规则只消耗true/false。块中的声明也可以出现在其他语句之后。AST Builder仍是单独的过渡构造层，不宣称已经改造成Clang前端。

## 3. 修改前后与函数职责

### Type与函数签名

include/my_compiler/ast.hpp新增TypeKind和Type。Parameter、Statement声明、Function返回值都携带Type；Structure记录成员次序与源码声明次序。Expression还记录语义检查后的type、二元运算的operand_type，以及member_index。

原FunctionSignature只按参数个数检查，新Signature还保存返回类型与逐个参数类型，因此float f(float x)与double f(double x)不再仅因为都只有一个参数就算相容。原型参数名可以不同；调用点仍须先看见声明或定义。

### Builder::primary、type、structure

- type消费基础类型或struct Tag；structure构造顶层结构体及成员清单。
- primary识别字符、小数、科学记数法、布尔值与数值cast，并把p.inner.x构造为两层Member节点。
- expression继续使用优先级爬升；并没有因为加入浮点重新实现一套运算符结合规则。
- function区分有值返回和void的return;，保留末尾返回的范围限制。
- statement把赋值左侧保存为一棵地址表达式，而非只保存一个字符串变量名。

原先字符和浮点格式必须拒绝的两项旧AST测试，现改为检查成功AST；printf("%f", 5)仍拒绝，因为可变参数不会为了格式串把一个int自动改传double。这不是删除旧回归来凑通过。

### Checker::expression与conversion

前端负责确定“这个运算该是什么类型”，后端不能靠LLVMValue临时猜源语言规则。例如：

```c
float half(float x) { return x * 0.5f; }
double add(double x, int y) { return x + y; }
char next(char x) { return x + 1; }
```

第一项是float乘法；第二项先把y转换成double再做浮点加法；第三项先把char提升成int计算，再在返回处缩回char。比较表达式的源语言结果仍是int的0/1。非数值对象不能算术或充当条件；结构体只允许相同tag之间按值复制，成员布局碰巧一样也不能把struct P隐式当struct Q。

### Checker::place与初始化路径

旧Binding只有一个initialized布尔值，新Binding保存对象类型及已初始化的叶成员路径。标量使用空路径；例如p.inner.x使用inner.x。

```c
struct P { int x; double y; };
int main(void)
{
    struct P p;
    p.x = 7;
    printf("%d\n", p.x);  /* 合法：只读取已初始化的x */
    /* struct P q = p;    拒绝：整值复制会读取尚未初始化的y */
    return 0;
}
```

place只定位对象或成员，不读取其值。赋值右侧检查通过后，initialize才登记相应路径；读表达式则由require_initialized检查所需全部叶成员。内层遮蔽继续使用独立绑定。if两支分别检查并对路径集合求交；一支写x、另一支写y不能合并成整个p已初始化。while可能零次运行，所以出口仍沿用入口状态。

### Lowering::type、create_slot与address

旧create_slot固定CreateAlloca(i32)，新实现通过Type映射为i8/i1/i32/float/double或llvm::StructType。结构体按成员顺序交给LLVM目标DataLayout布局；没有手工假设double紧跟char的第一个字节。

成员左值通过CreateStructGEP得到地址，再按成员类型load/store；从函数返回的临时结构体取成员则使用extractvalue。GEP计算地址，不会自己执行一次内存读取。结构体整值复制使用聚合值load/store，参数按值传递，因此被调函数修改自己的p不会回写调用者的p。

### Lowering::convert、truth与expression

- 整数宽度转换使用有符号扩展/截断，bool扩展用零扩展。
- int/char到浮点使用SIToFP，bool到浮点使用UIToFP；float到double用FPExt，反向用FPTrunc。
- 浮点转整数用FPToSI；转bool使用“与零比较”，不能直接截取最低位。
- 浮点运算使用fadd/fsub/fmul；整数运算继续add/sub/mul。
- 浮点比较的!=和真值判断使用unordered-not-equal，让NaN按非零/不相等处理；其余大小关系使用ordered比较。
- void调用不命名一个不存在的结果，并生成ret void；不能为void分配变量槽位。

### printf默认参数提升

格式检查确定转换项与实参匹配，后端再执行默认参数提升。例如float x=1.5f; printf("%.1f", x);必须传double。char和bool按int传入；%s仍只接受字符串字面量。标准printf的实现来自libc，仍由Clang驱动链接，不是本项目重写。

### 为什么结构体互调先限定在一个翻译单元

LLVM聚合函数类型并不自动等于平台C ABI。外部C函数可能拆寄存器、用byval或隐藏sret指针传结构体。当前内部结构体函数的调用与定义使用同一套LLVM签名，并设置internal链接；没有本翻译单元定义的结构体按值外部原型报E_SEMA_ABI。对普通char/bool标量签名则补上signext/zeroext，并用Clang调用程序做双向验证。

对应原理可查[LLVM18类型与结构体](https://releases.llvm.org/18.1.8/docs/LangRef.html#structure-types)、[转换指令](https://releases.llvm.org/18.1.8/docs/LangRef.html#conversion-operations)、[参数属性](https://releases.llvm.org/18.1.8/docs/LangRef.html#parameter-attributes)。实际使用的本机LLVM为18.1.3，源码接口以本机头文件为准；没有为这次扩展安装依赖。
